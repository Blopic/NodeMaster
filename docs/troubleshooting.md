# NodeMaster 故障排查

| 现象 | 处理方式 |
| --- | --- |
| 找不到 Python 或 npm | `run.bat` 优先使用已有的 `.venv`，首次创建时依次检查 `py -3.11`、`py -3` 和 PATH 中的 `python`，要求解释器可运行且版本至少为 3.11。安装 Python 时将其加入 PATH。需要构建界面时安装 Node.js 22 或更新版本，再重新打开终端。 |
| 无法停止应用 | 在同一项目目录运行 `stop.bat`。如果启动时通过环境变量设置了 `NODEMASTER_DATA_DIR`，停止时使用相同值。也可以在启动窗口按 Ctrl+C。 |
| 浏览器提示无法连接 | 保持启动窗口开启，检查依赖安装错误，并使用窗口打印的实际地址。开启代理时，检查浏览器或系统代理的例外列表是否包含 `127.0.0.1` 和 `localhost`。参见下面的命令行验证步骤。 |
| 来源刷新失败 | 检查链接是否直接返回 UTF-8 清单，格式是否选对。GitHub 链接需指向单个文件。远程来源只接受解析到公网地址的目标，并且不跟随重定向。 |
| 远程来源或直连出口提示目标地址不可用 | 用 `Resolve-DnsName` 查询对应域名的 A 和 AAAA 记录。如果返回代理用于模拟地址的 `198.18.0.0/15` 网段，检查代理客户端的 DNS Fake IP、过滤名单或分流设置，让这些域名返回真实公网地址。 |
| 代理出口查询超时 | 在设置页显式填写代理监听地址，核对协议、主机、端口和所需认证，并确认代理正在监听且能访问出口查询服务。 |
| CDN 的 TCP 可连但 HTTPS 失败 | 核对端口、SNI、HTTP Host、路径和证书。TCP 成功不能证明 HTTPS 成功。 |
| TURN 的 UDP 检测超时 | 检查防火墙和上游网络是否允许 UDP。服务支持 TCP 或 TLS 时，可将不同传输分别导入并测试。 |
| TURN 已分配中继并绑定通道，但未收到回包 | 在「设置 → 检测目标」选「使用 Cloudflare STUN」或填写自己的 UDP 原样回显目标，保存后点「从本机验证目标」。本机验证通过后，再运行「TURN 代理中继测试」确认 TURN 节点也能往返该目标。普通 HTTPS 地址可能没有可用的 UDP 回显。 |
| TURN 测试进度更新慢 | 查看任务中的「TURN 分配与 UDP 中继验证」和「更新历史对比与推荐」阶段。快速测速每个节点只采样一次。按设置测速时，采样次数、连接超时和并发会影响耗时。UDP 响应超时直接记入当次采样结果。 |
| IP 有地区但 IP 类型显示未知 | 在 TURN / STUN 列表重新运行「查询 IP 质量」。默认会用 IPQuery 补查其他来源未提供的托管和移动网络标记，已有的地区缓存可以继续使用。配置支持用途数据的服务可补充家宽、商宽等分类。来源缺少证据或用途冲突的记录仍会显示未知。 |
| IP 质量没有返回数据或提示限流 | 检查服务密钥、套餐和配额。查询只针对公网 IP；配额恢复前可使用缓存。 |
| 移动数据后无法解密 | 停止应用，恢复同一备份中的 SQLite 数据和 local.key。不要删除密钥。 |

分享日志或导出样本前，删除订阅链接、代理认证信息和密钥。

## 通过命令行检查本机连接

在单独的 PowerShell 会话中为命令行客户端设置本机代理例外。将示例中的端口换成启动窗口打印的端口。

    $env:NO_PROXY = '127.0.0.1,localhost'
    curl.exe http://127.0.0.1:8765/api/health

该变量只在当前 PowerShell 会话及其子进程中生效。如已有例外，请将这两个地址追加到原列表。
