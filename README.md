# NodeMaster

NodeMaster 是运行在 Windows 本机的网络节点管理和检测工具。CDN 优选 IP、TURN/STUN 节点和代理出口分别记录，检测历史保存在 SQLite 中。

## Windows 10/11 安装

1. 解压 [GitHub Releases](https://github.com/Blopic/NodeMaster/releases) 中的 Windows ZIP，安装 Python 3.11 或更新版本，并在安装时将 Python 加入 PATH。发布包已包含构建好的页面。从源码自行构建时需另装 Node.js 22 或更新版本。
2. 双击 `run.bat`。脚本优先使用已有的 `.venv`。首次启动按 `py -3.11`、`py -3`、PATH 中的 `python` 的顺序，选择首个可运行且版本至少为 3.11 的解释器创建环境。脚本会安装 Python 依赖，缺少页面时也会安装前端依赖并构建。首次下载依赖需要联网。
3. 在浏览器打开启动窗口打印的地址，默认 <http://127.0.0.1:8765>。如遇端口占用，以实际打印的地址为准。开启代理时，可将 `127.0.0.1` 和 `localhost` 加入浏览器或系统代理例外。命令行客户端可使用当前会话的 `NO_PROXY`。具体设置参阅[故障排查](docs/troubleshooting.md)。
4. 在同一项目目录双击 `stop.bat`，或在另一个终端运行它。脚本会停止同一数据目录下的实例。若启动时通过环境变量指定了 `NODEMASTER_DATA_DIR`，停止时也要使用相同值。也可在启动窗口按 Ctrl+C，若系统询问是否终止批处理，输入 Y。

## 使用说明

- 节点导入接受 TXT、CSV、JSON、YAML 和常见 URI。CDN 文本可混用 IP 和域名，每行可附端口和名称，例如 `example.com:443#示例节点`。普通清单保留所有有效记录，文件大小最多 2 MiB。Cloudflare 官方网段和自定义 CIDR 按设置抽样。
- 在「来源与订阅 → 批量导入直链」每行填一个 HTTPS 文件地址，也可上传 UTF-8 TXT 地址列表。CDN 候选请选择「优选 IP 来源」。应用会为每条有效直链建立一个来源，并显示各来源的读取数量和错误。
- 可以直接粘贴 GitHub 文件页面链接。CheckTurn 等带「中继」列的 CSV 会按 TURN / STUN 节点导入，出口 IP、国家、带宽等来源数据保存在备注中。
- 节点查询和导入默认只读取数据。可点单行「测速」，或在「批量测速」中选择已勾选、所有筛选结果（含其他页）或所有节点。快速测速使用单次采样、较短超时和最多 64 KiB 下载量。需要完整采样时，选择「按设置测速」。
- CDN 测试按候选 IP 建立连接，使用设置中的域名、SNI、Host 和路径。「TURN 服务测试」检查 Binding 和 TURN 分配。「TURN 代理中继测试」通过 TURN 通道验证实际 UDP 收发，可在「设置 → 检测目标」选用 Cloudflare STUN 或配置自己的 UDP 原样回显端点。
- IP 质量查询参照 [IPQuality](https://github.com/xykt/IPQuality) 的多来源交叉展示方式。DB-IP 默认提供免密钥的地区查询，缺少有效地区时由 IPWhois 补查。使用默认 Cloudflare HTTPS 目标测速时，列表优先展示响应头里的实测 CDN 边缘机房，节点详情同时显示 IP 数据库地区。实测机房随网络和路由变化。缺少内置地区映射的机房会显示原始代码。
- 家宽、商宽、教育网、托管和移动网络等类型取自查询服务的用途数据。TURN / STUN 节点查询缺少类型时，默认用 IPQuery 补查托管或移动网络标记，可在设置里关闭。可配置支持用途数据的 ipapi.is、IPinfo 或 AbuseIPDB 细分类型。证据缺失或相互冲突时显示「未知」。默认 Cloudflare 测速获得边缘机房时也可识别 CDN 类型。
- 在「定时计划」选择「直链变更检测」。文件变化后，计划合并本次和上次清单中的节点，对启用的 CDN、TURN 和 STUN 节点测速。可设置每个来源淘汰的数量，优先淘汰失败、部分通过及评分较低的已测节点，填 0 表示本轮不淘汰。今后由计划淘汰的节点会在该来源的后续更新中跳过，仍可在节点管理中查看原节点及历史。
- 「节点管理」默认打开「CDN / 优选节点」，可切换到「TURN / STUN」做批量代理中继测试。协议、检测状态、地区、IP 类型均可多选。同一项命中任一选项即可，不同项需同时满足。「保存筛选配置」会按分类写入数据目录的 `node-filters.json`，重新打开会自动套用。
- 「工作台 → 候选推荐」按 CDN、TURN 中继和 TURN / STUN 服务分别查看榜单。综合推荐使用稳定性、下载速度、延迟和 IP 质量评分。权重可在「设置 → 评分与更新」修改。各项按实际可用数据计分，TURN 没有下载速度项。地区、IP 类型和性能门槛可进一步缩小推荐范围。
- 「用筛选结果覆盖节点」可预览并确认保留当前分类的全部匹配节点。覆盖前会备份，移出的节点保留历史，后续直链刷新和定时计划会跳过它们。手动重新导入节点内容可恢复。
- 节点管理和工作台榜单都支持批量导出与复制，按当前排序输出。榜单可选择当前显示项或全部匹配项，也可以点击节点地址单独复制。
- TXT 可附加自定义注释，例如 `$country · $ip_type_label · $latency_ms ms`。自定义模板可用 `$address` 输出带端口和协议前缀的地址。CSV、JSON 和 YAML 同时保存检测状态、地区和 IP 类型。各格式默认省略凭据。
- TURN 完整中继任务结束后，可从任务详情导出通过的中继。选择「优选 IP + TURN 中继」，填写优选地址和注释，即可生成如 `38.55.198.28:8443#HK转巴拉圭家宽1$turn://45.183.62.27:3478` 的条目。工作台的 TURN 中继榜单也支持此格式。
- 计划在应用运行时执行。应用重启会恢复计划，未结束的任务会标记为中断。
- SS、VMess、VLESS、Trojan、HTTP/HTTPS 和 SOCKS5 可以管理；这类节点未提供独立协议测速。查询代理出口时，在设置页填写已启动的代理地址。EdgeTunnel 可尝试通用清单或模板，暂无专用格式适配。

## 配置、迁移和测试

将 .env.example 复制为 .env 后可设置端口、数据目录及是否自动打开浏览器。数据库在启动时初始化和迁移。备份或迁移前请停止应用并复制整个 runtime 目录（或实际配置的数据目录），保留数据库及其 local.key 文件。

在项目根目录使用 PowerShell 安装测试依赖和运行测试：

    .\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
    .\.venv\Scripts\python.exe -m pytest -q
    npm.cmd --prefix frontend ci
    npm.cmd --prefix frontend run build

协议测试使用本机服务，第三方 API 测试使用模拟响应。技术选型、数据结构和接口见 [架构文档](docs/architecture.md)。安装或检测失败时，参阅 [故障排查](docs/troubleshooting.md)。
